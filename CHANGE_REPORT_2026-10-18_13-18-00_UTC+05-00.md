## 2. Реализованные артефакты

### `internal/logic/errors.go`

Типизированная модель ошибок модуля M3:

```go
type DeviceOperationError struct { Kind DeviceOperationErrorKind; Err error }
type ValidationError       struct { Field, Message string }

var ErrEmptyPassword = &ValidationError{Field: "password", ...}
var ErrEmptyChallenge = &ValidationError{Field: "challenge", ...}
```

- Соответствует контракту `logic.md` (строки 38–53).
- Сентинели поддерживают `errors.Is` / `errors.As` без пользовательского `Is()`.
- Тексты ошибок не раскрывают значения password, challenge или дайджеста.

### `internal/logic/hash.go`

Реализация `CalculateHash(password, challenge string) (string, error)`:

- Алгоритм: `crypto/sha256` over UTF-8(`password + challenge`) → `encoding/hex`.
- Результат: 64-символьная строка `[0-9a-f]` (lowercase hex).
- Валидация: если любой из аргументов пуст — возврат типизированной `ValidationError`.
- Зависимости: только стандартная библиотека Go (`crypto/sha256`, `encoding/hex`).
- Безопасность: не логирует и не раскрывает входные данные в ошибках.

### `internal/logic/calculate_hash_test.go`

Полный TDD-набор из 6 тест-функций и 14 подтестов:

| Тест-функция | Что проверяет |
|---|---|
| `TestCalculateHash_PositiveVectors` | 5 эталонных SHA-256 векторов (ASCII, Unicode, пробелы) |
| `TestCalculateHash_OutputFormatting` | Regex `[0-9a-f]{64}`, длина 64, lowercase |
| `TestCalculateHash_OrderSensitivity` | hash(A,B) ≠ hash(B,A) |
| `TestCalculateHash_NegativeScenarios` | Пустой password, пустой challenge, оба пустые; `errors.Is` + `errors.As` |
| `TestCalculateHash_SecurityNoDisclosures` | Текст ошибки не содержит canary-значения |
| `TestCalculateHash_Concurrent` | 50 горутин × 100 итераций (data-race free) |

### `internal/logic/errors_test.go`

Юнит-тесты типов ошибок: `ValidationError.Error()`, `DeviceOperationError.Error()`, `Unwrap()`, `errors.Is`.
