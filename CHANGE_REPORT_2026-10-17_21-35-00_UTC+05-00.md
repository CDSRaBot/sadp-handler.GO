# Отчёт по согласованию контрактов между модулями (Фаза 3)

**Основание:** проход фазы 3 «Рекурсивный аудит спецификаций» по [руководству по разработке](docs/ru/DEVELOPMENT_GUIDE.md) — устранение разрывов в цепочках данных, типизация моделей ошибок и взаимная увязка интерфейсов модулей M0–M6.

## 1. Краткий итог

Выполнен полный цикл взаимного согласования контрактов, структур данных и моделей ошибок между всеми модулями проектируемой системы. В спецификациях устранены разрывы передачи данных от пользовательского ввода до сетевого уровня:

- **Лимит датаграмм:** введён единый настроечный параметр `maxDatagramSize` (по умолчанию `DefaultMaxSADPDatagramSize = 1500`, допустимый диапазон `1..65507`), проходящий по цепочке `M4 (Settings) -> M6 (DiscoveryOptions) -> M1 (Listen, SendSADPDatagram) / M2 (ParseAdvertisement)`.
- **Типизация сетевого транспорта (M1):** введена структура ошибки `TransportError` с перечислением стабильных этапов `TransportStage` (`validation`, `encode`, `write`, `short_write`, `read`, `dispatch`, `close`).
- **Транспорт произвольных датаграмм (M1):** специфицирована новая атомарная процедура **P1.4** `SendSADPDatagram` (`send_datagram.md`), необходимая для команд управления SADP (активация, смена сети).
- **Типизация ошибок парсера (M2):** введена структура ошибки `ParseError` со стабильными категориями `ParseErrorKind` (`empty_datagram`, `oversized_datagram`, `malformed_xml`, `unsupported_message`, `missing_field`, `invalid_field`).
- **Спецификация логики устройств (M3):** зафиксирован подтверждённый алгоритм challenge-response `SHA-256(UTF-8(password + challenge))` и XML-форматы активации и настройки сети. Разграничены понятия протокольного подтверждения (форматы XML и вычисление хеша подтверждены экспериментами) и ограничения текущей реализации (команды временно заблокированы в UI статусом `unsupported` до написания сквозного цикла сессии).
- **Отказоустойчивость локализации (M5):** добавлен sentinel `ErrNoExternalLocales`, гарантирующий штатный запуск со встроенным английским каталогом при отсутствии внешней папки переводов.
- **Единый диспетчер команд (M4):** выровнены возвращаемые результаты `CommandResult` и типизированные коды сбоев `FailureInvalidArgument`, `FailureUnsupported`, `FailureOperationFailed`, `FailureCanceled`.
- **Двуязычный паритет:** обеспечено 100% совпадение контрактов Go-кода, констант и структур во всех 35 парах англоязычных и русскоязычных спецификаций.

Объём изменений в спецификациях: **49 файлов изменены, 2 новых файла добавлены (`docs/spec/procedures/network/send_datagram.md` и `docs/ru/spec/procedures/network/send_datagram.md`)**.

## 2. Выполненные изменения по модулям

### Системная спецификация (`SYSTEM.md`, `ru/spec/SYSTEM.md`)
- Зафиксирован статус верификации: формат SADP-активации по MAC и вычисление хеша challenge-response `SHA-256(UTF-8(password + challenge))` приняты как подтверждённые практикой.
- Уточнено, что блокировка команд `activate` и `network` в CLI/TUI является ограничением текущего этапа реализации (отсутствие сквозного транспорта ответов и конечного автомата сессии), а не нерешённым вопросом формата пакетов.
- Включена поддержка настройки `network.max_sadp_datagram_size`.

### M0: Адаптер платформы (`adapter.md`, `open_multicast.md`)
- Уточнено владение сокетом `net.PacketConn`: создаётся в M0, принадлежит вызывающей стороне (M6), которая может передать владение в M1 `Listen` (закрывающему сокет при выходе).
- Уточнены требования к одновременному наличию одного читателя (`ReadFrom`) и одного сериализованного писателя (`WriteTo`) на одном интерфейсе.

### M1: Сетевое ядро (`network.md`, `listen.md`, `send_probe.md`, `send_datagram.md`, `datagram_received.md`)
- Введена типизированная ошибка `TransportError` с сохранением исходной причины через `Unwrap()` и фиксацией этапа сбоя (`TransportStage`).
- В сигнатуру `Listen` добавлен параметр `maxDatagramSize int`. Чтение выполняется в буфер размером `maxDatagramSize + 1` байт для гарантированного обнаружения усечения датаграмм вместо скрытого разбора неполных данных.
- Добавлена новая процедура **P1.4 `SendSADPDatagram`**: отправка ровно одной подготовленной датаграммы без передачи владения сокетом, ожидания ответа или автоматических повторов.
- Процедура P1.2 `SendInquiryProbe` синхронизирована с `TransportError` на этапах валидации, кодирования XML и записи.

### M2: Парсер данных (`parser.md`, `parse_advertisement.md`)
- В сигнатуру `ParseAdvertisement` добавлен параметр `maxDatagramSize int`.
- Введена структура `ParseError{Kind, Field, Err}` со стабильными видами ошибок `ParseErrorKind`.
- Сохранено правило безопасного разбора XML: недоверенные байты, отсутствие внешних сущностей, изоляция чувствительных полей (`Salt`, учетные данные).

### M3: Логика устройств (`logic.md`, `build_activation.md`, `build_network.md`, `calculate_hash.md`)
- Формат формирования XML активации (`<Activate><TargetMAC>...<Password>...`) и сетевых настроек (`<NetworkParameter>...<SecurityResponse>...`) подтверждён на основе практических перехватов и Python-референса.
- Подтверждён алгоритм P3.5 `CalculateHash`: SHA-256 от UTF-8 строки `password + challenge` в нижнем шестнадцатеричном регистре.
- Запрещён переход на открытую передачу пароля (`<Password>` открытым текстом) при отсутствии challenge (отказ от небезопасного fallback из Python-референса).
- Требования к сетевой конфигурации: статический IPv4 требует обязательного указания шлюза (`--gateway`), а при включённом DHCP статический адрес и шлюз запрещены.

### M4: Интерфейс пользователя (`ui.md`, `dispatch_command.md`, `parse_cli_command.md`, `parse_command.md`, `select_mode.md`)
- Добавлена структура настроек:
  ```go
  type Settings struct {
      Language string          `json:"language,omitempty"`
      Network  NetworkSettings `json:"network,omitempty"`
  }
  type NetworkSettings struct {
      MaxSADPDatagramSize int `json:"max_sadp_datagram_size,omitempty"`
  }
  ```
- В `DispatchCommand` зафиксированы строковые константы ошибок:
  ```go
  const (
      FailureInvalidArgument = "invalid_argument"
      FailureUnsupported    = "unsupported"
      FailureOperationFailed = "operation_failed"
      FailureCanceled        = "canceled"
  )
  ```
- Команды `ActivateCommand` и `NetworkCommand` при вызове диспетчера немедленно возвращают ошибку со статусом `unsupported` до запроса пароля, открытия форм ввода или сетевых обращений.

### M5: Локализация (`localization.md`, `load.md`, `list_locales.md`, `decode_catalog.md`)
- Введён sentinel `ErrNoExternalLocales`: если внешняя папка локалей отсутствует или не содержит `.json` файлов, `ListLocales` возвращает `["en"]` и данную ошибку. M4 обрабатывает это штатно и продолжает работу со встроенным английским каталогом.

### M6: Координатор обнаружения (`discovery.md`, `discover_on_interface.md`)
- В структуру `DiscoveryOptions` добавлено поле `MaxSADPDatagramSize int`.
- Процедура P6.1 `DiscoverOnInterface` передаёт настроенный лимит в M1 `Listen` и M2 `ParseAdvertisement`.
- Чётко определена схема параллелизма: ровно один читатель `Listen` и ровно один сериализованный планировщик отправки probe на одном интерфейсе.

### Пользовательская справка (`docs/HELP.md`, `docs/ru/HELP.md`)
- Синхронизированы правила запуска CLI: флаги `--ui=no`, `--once`, `--format text|json`, `--lang CODE`.
- Уточнено поведение команд `activate` и `network` в нереализованном состоянии: завершение с ошибкой `unsupported` без запроса пароля.

## 3. Сводная таблица согласованных межмодульных контрактов

| Связка модулей | Передаваемые типы данных | Механизм согласования и валидации |
|---|---|---|
| **M4 -> M6** | `adapter.Interface`, `DiscoveryOptions` | Валидация интерфейса и лимита `MaxSADPDatagramSize` (1..65507). |
| **M6 -> M0** | `adapter.Interface`, `netip.AddrPort` (`239.255.255.250:37020`) | Открытие `net.PacketConn`, проверка прав и поддержки мультикаста на интерфейсе. |
| **M6 -> M1** | `conn net.PacketConn`, `maxDatagramSize`, `PacketHandler` | Передача владения сокетом в `Listen`. Гарантия закрытия сокета при завершении. |
| **M1 -> M6 -> M2** | `raw []byte`, `sender net.Addr`, `maxDatagramSize` | Проверка длины буфера в M1 (`handleDatagram`), парсинг в M2 `ParseAdvertisement`, возврат `Device` или `ParseError`. |
| **M6 -> M4** | `discovery.Event` (`DeviceFound` / `DatagramRejected`) | Доставка событий в цикл событий UI, дедупликация и агрегация в `DiscoveredDevice` по ключу `(MAC, sender)`. |
| **M4 -> M3** | `TargetSelector`, `PasswordSource`, `NetworkConfig` | Валидация входных параметров до сетевых действий; блокировка `unsupported` до готовности сквозного воркфлоу. |
| **M3 -> M1** | `conn net.PacketConn`, `target net.Addr`, `payload []byte`, `maxDatagramSize` | Подготовка XML в P3.1/P3.2 и передача в P1.4 `SendSADPDatagram` без ожидания ответа. |
| **M4 -> M5** | `cliLang`, `configLang`, fallback `"en"` | `ResolveLocale`, загрузка каталога, обработка отсутствия внешних локалей через `ErrNoExternalLocales`. |
