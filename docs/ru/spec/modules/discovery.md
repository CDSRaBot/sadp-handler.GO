# Спецификация модуля: M6 — Координатор обнаружения

## 1. Назначение

Объединять настройку multicast на выбранном интерфейсе в M0, отправку inquiry и приём датаграмм в M1, а также разбор объявлений в M2 в один отменяемый сеанс обнаружения.

## 2. Обязанности

- Выполнять один сеанс обнаружения на одном явно выбранном интерфейсе.
- Поддерживать открытое одно SADP multicast-соединение во время отправки inquiry-probe и непрерывного приёма/разбора объявлений согласно проверенной непрерывной либо ограниченной циклической политике.
- Передавать вызывающей стороне корректные устройства и диагностические события отклонённых датаграмм, не раскрывая содержимое пакетов и поля безопасности.
- Явно определять владение соединением, отмену, ошибки callback и очистку.

M6 не перечисляет и не выбирает интерфейсы, не сопоставляет UUID и не интерпретирует ответы управления устройствами или безопасности. Расписание probe задаётся приложением и не является протокольной политикой повторов. Вызывающая сторона может запускать отдельные сеансы для отдельных интерфейсов и отвечает за политику их совместной работы.

## 3. Контракт API Go

```go
type EventKind uint8

const (
    DeviceFound EventKind = iota + 1
    DatagramRejected
)

type Event struct {
    Kind       EventKind
    Device     *parser.Device
    Sender     net.Addr
    ObservedAt time.Time
    Err        error
}

type EventHandler func(context.Context, Event) error

type DiscoveryOptions struct {
    ProbeInterval time.Duration
    CycleTimeout  time.Duration
    RepeatCount   int
}

func DiscoverOnInterface(
    ctx context.Context,
    iface adapter.Interface,
    options DiscoveryOptions,
    handle EventHandler,
) error
```

- Для `DeviceFound` поле `Device` ненулевое, а `Err` равен nil. Для `DatagramRejected` поле `Device` равно nil, а `Err` ненулевое. Если отправитель доступен, `Sender` сохраняется в обоих типах событий. `ObservedAt` фиксирует время, когда M6 принял датаграмму в обработку.
- Отклонять nil-контекст, nil-обработчик и неподходящий интерфейс до запуска сеанса.
- Использовать наблюдаемый совместимый endpoint `239.255.255.250:37020`. Менять endpoint можно только явным будущим изменением API/спецификации, а не незаметным fallback.
- Непрерывный режим требует `ProbeInterval > 0`, `CycleTimeout == 0` и `RepeatCount == 0`; probe отправляется немедленно, затем с заданным интервалом при работающем цикле приёма.
- Ограниченный режим требует `ProbeInterval == 0`, `CycleTimeout > 0` и `RepeatCount` в диапазоне `1..100`; probe отправляется сразу, после чего приём продолжается в течение полного timeout, а следующий цикл начинается немедленно. Событие найденного устройства цикл не завершает.
- Отклонять смешанные, отсутствующие, неположительные и выходящие за диапазон временные политики до открытия сокета. Эти параметры задают расписание приложения, но не требования времени SADP.
- Контекст сеанса управляет запланированными отправками; `Listen` получает дочерний контекст, который M6 отменяет только после остановки и завершения отправителя при штатном завершении. Это оставляет закрытие соединения за `Listen` и предотвращает гонку штатного закрытия с запланированной записью. Если `Listen` завершается ошибкой раньше, он может закрыть соединение во время выполняющейся записи; необходимо дождаться отправителя и сохранить обе ошибки. Возвращать nil только при штатной отмене сеанса и успешной очистке; возвращать ошибки сокета, отправки, приёма, закрытия и обработчика вызывающей стороны.

## 4. Контракт событий

- `DeviceFound` содержит разобранное `parser.Device`; `DatagramRejected` сообщает об ошибке разбора/проверки, не раскрывая исходные данные.
- Для каждого пакета событие содержит адрес отправителя и время наблюдения.
- Ожидаемая ошибка разбора превращается в событие `DatagramRejected`; продолжать приём можно, только если обработчик события вернул nil.
- Сбой обработчика завершает сеанс и возвращается вызывающей стороне с контекстом стадии.

## 5. Тестирование

Подменять зависимости M0/M1/M2 на границе реализации непубличным набором зависимостей или эквивалентными функциональными точками для открытия, отправки, приёма и разбора. Экспортируемый `DiscoverOnInterface` использует рабочие зависимости, а тесты вызывают внутреннюю оркестрацию с имитациями. Не добавлять изменяемые глобальные переменные или тестовые параметры в публичный API.

Проверять валидацию политики, немедленную и периодическую отправку, точное число ограниченных циклов и длительность окон приёма, отсутствие досрочной остановки по событию устройства, конкурентное чтение/запись, очистку при сбое открытия/первой отправки, передачу владения, штатную отмену, события ошибки разбора с последующим продолжением приёма, доставку корректных `ProbeMatch` и `Hello`, сбои callback/отправки, сохранение отправителя и отсутствие полезной нагрузки в журналах. Тесты не должны требовать реальных устройств или multicast-доступа.
