# Спецификация модуля: M6 — Координатор обнаружения

## 1. Назначение

Объединить настройку multicast-соединения M0, отправку inquiry-probe и приём датаграмм M1, а также разбор объявлений M2 в один отменяемый сеанс.

## 2. Ответственность и границы

- Выполнять один сеанс на одном явно выбранном интерфейсе.
- Открыть одно соединение и передавать вызывающему коду каждое проверенное объявление и диагностическое событие; поддержать непрерывную и конечную расписанные политики отправки probe.
- Явно задавать владение соединением, отмену, обработку ошибок callback и очистку ресурсов.
- Использовать наблюдаемый endpoint `239.255.255.250:37020`.

Не выводить из расписания приложения протокольные требования к повторам, не сопоставлять UUID, не выбирать интерфейсы и не трактовать ответы управления устройством. Не считать, что `Hello` вызван конкретным probe. Каждый вызов обрабатывает один интерфейс; M6 передаёт все валидные события, а пользовательское представление агрегирует их отдельно.

## 3. Контракт API Go

Канонические типы и сигнатура `DiscoverOnInterface` приведены в [англоязычной спецификации M6](../../../spec/modules/discovery.md). Событие `DeviceFound` содержит устройство без ошибки; `DatagramRejected` — отправителя и безопасно сформированную ошибку без полезной нагрузки.

Отклонять nil-контекст, nil-обработчик и неподходящий интерфейс до сетевой активности. Возвращать nil только при штатной отмене и успешной очистке; ошибки сокета, отправки, приёма, обработчика и закрытия возвращать явно.

## 4. Жизненный цикл

1. Открыть multicast-соединение M0 для выбранного интерфейса.
2. Отправить одну датаграмму inquiry-probe через M1.
3. После успешной отправки передать владение соединением M1 `Listen`.
4. Для каждой датаграммы вызвать M2. Ошибку разбора передать событием отклонения и продолжить, если callback успешен.
5. Передать корректное объявление событием `DeviceFound`.
6. Не логировать полезную нагрузку и не выводить неподтверждённые правила повтора, корреляции или расписания.

Полный контракт типов, сигнатуры и политики — [нормативная P6.1 DiscoverOnInterface](../../../spec/procedures/discovery/discover_on_interface.md).

Для тестирования внедрять зависимости M0/M1/M2 через непубличную структуру зависимостей или эквивалентные функциональные точки для открытия, отправки, приёма и разбора. Экспортируемый API не содержит тестовых параметров; изменяемые глобальные переменные не использовать.
