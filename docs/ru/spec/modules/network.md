# Спецификация модуля: M1 — Сетевое ядро

## 1. Назначение

Управлять UDP-трафиком SADP: отправлять inquiry-probe, принимать ответы устройств и передавать полезные данные обработчику. Реализация на Python проверена на реальных устройствах и успешно находит их и получает ответы; её поведение является базой совместимости для этого модуля. Перехваты HiToolsDelivery документируют формы inquiry, `ProbeMatch` и `Hello`, но не задают универсальные правила корреляции ответов или таймингов. Модуль использует сетевые API Go и не зависит от цикла событий или конкретного CLI.

## 2. Обязанности

- Принимать UDP-датаграммы и сохранять сведения об отправителе для последующей проверки.
- Формировать и отправлять inquiry-probe на настроенный multicast endpoint, сохраняя рабочее поведение реализации на Python.
- Использовать отмену, дедлайны и ограниченную обработку пакетов, чтобы остановка была предсказуемой, а некорректный трафик не приводил к исчерпанию ресурсов.
- Передавать вызывающему коду ошибки транспорта и обработчика; разбор данных и решения по управлению устройствами остаются за пределами этого модуля.
- Обрабатывать пакеты синхронно или с явным ограничением параллелизма. Успешное обнаружение реальных устройств является базой; сами перехваты не задают универсальные правила разбора ответов, корреляции, повторов и таймингов.

## 3. Контракт API Go

Следующие сигнатуры описывают контракт модуля; конкретные пути пакетов и экспортируемые имена будут окончательно определены при реализации:

```go
type PacketHandler func(context.Context, []byte, net.Addr) error

const DefaultMaxSADPDatagramSize = 1500

type TransportStage string

const (
    TransportValidation TransportStage = "validation"
    TransportEncode     TransportStage = "encode"
    TransportWrite      TransportStage = "write"
    TransportShortWrite TransportStage = "short_write"
    TransportRead       TransportStage = "read"
    TransportDispatch   TransportStage = "dispatch"
    TransportTimeout    TransportStage = "timeout"
    TransportCanceled   TransportStage = "canceled"
    TransportResponseTooLarge TransportStage = "response_too_large"
    TransportClose      TransportStage = "close"
)

type TransportError struct {
    Stage TransportStage
    Err   error
}

func (e *TransportError) Error() string
func (e *TransportError) Unwrap() error

func Listen(ctx context.Context, conn net.PacketConn, maxDatagramSize int, handle PacketHandler) error
func SendInquiryProbe(ctx context.Context, conn net.PacketConn, target net.Addr) error
func SendSADPDatagram(
    ctx context.Context,
    conn net.PacketConn,
    target net.Addr,
    payload []byte,
    maxDatagramSize int,
) error
```

- `Listen` отклоняет nil-контекст, соединение или обработчик, а также `maxDatagramSize` вне диапазона `1..65507`. При вызове владение ненулевым соединением передаётся `Listen`; функция закрывает его при любом исходе, чтобы отмена разблокировала чтение и сокет не утёк.
- `Listen` принимает пакеты, пока контекст не будет отменён или не произойдёт ошибка транспорта. При штатной отмене возвращает `nil`, при неожиданной ошибке транспорта или обработчика — ненулевую ошибку.
- `SendInquiryProbe` отправляет ровно одну датаграмму, не ожидает ответа и не повторяет запрос; владение соединением не передаётся.
- `SendSADPDatagram` отклоняет nil/пустые аргументы, некорректный лимит и payload больше `maxDatagramSize`; отправляет ровно одну датаграмму на переданный адрес, не владеет соединением и не ожидает ответа. M3 использует эту функцию для SADP XML управления, включая активацию; семантику ответа она не интерпретирует.
- `MutationTarget` содержит MAC-адрес целевого устройства и ожидаемый адрес отправителя. `MutationExchange` содержит фактический адрес отправителя и ограниченные байты ответа.
- `MutationTransport.Exchange` — единственная граница M1, которая может объединять отправку команды управления и получение ответа. Она проверяет target, payload, context и deadline, отправляет ровно один payload, принимает только ограниченные датаграммы и возвращает байты ответа вместе с фактическим sender. Разбор XML, решение об успешности и повторы остаются за вызывающим кодом.
- Транспорт, открывающий собственное соединение для `Exchange`, владеет им и закрывает на всех путях. При работе с соединением вызывающего кода ownership остаётся у вызывающего кода; транспорт обязан документировать сериализацию записи и чтения. Ответ от sender, не совпадающего с target, передаётся на корреляцию и никогда не считается успешным обменом.
- Ошибки `Exchange` классифицируются как validation, write, read, timeout, cancellation, oversized-response или close; исходная причина сохраняется для `errors.Is`/`errors.As`. Текст ошибки не содержит payload.
- Во время сессии M6 `Listen` может читать соединение, пока координатор последовательно выполняет записи M6/M3. Координатор останавливает и дожидается writer до отмены listener; при раннем сбое listener может закрыть соединение во время записи, а координатор сохраняет обе ошибки. После передачи ownership другие callers соединение не используют.
- Обработчик получает байты пакета и адрес отправителя. После возврата он не должен сохранять или изменять срез байтов, если предварительно не скопировал данные.
- Вызывающий код владеет соединением, возвращённым M0, до передачи его в `Listen`; после передачи соединение нельзя использовать повторно. Для быстрой остановки при отмене контекста прослушиватель закрывает переданное соединение и тем самым разблокирует ожидающее чтение.

## 4. Параллелизм и жизненный цикл

- Использовать горутины только тогда, когда они упрощают неблокирующий ввод-вывод или независимую работу; у каждой горутины должны быть ограниченный срок жизни и определённый способ остановки.
- Не запускать неограниченное число горутин — по одной на каждую датаграмму. Обработка должна быть последовательной либо использовать явно ограниченный пул работников.
- Сохранять порядок пакетов при параллельной обработке только в том случае, если этого требует контракт следующего уровня; в противном случае задокументировать поведение.
- Не отбрасывать незаметно ошибки обработчика или сокета. M2 явно возвращает ошибки разбора; обработчик уровня приложения решает, нужно ли ожидаемое некорректное объявление отбросить, учесть или сообщить о нём, и делает это решение наблюдаемым. Неожиданные ошибки обработчика передаются через `Listen`.

## 5. Проверка данных и безопасность

- Использовать настроенный `maxDatagramSize` для приёма и проверки парсером. Значение по умолчанию — `DefaultMaxSADPDatagramSize = 1500`, получаемое из файла настроек; допустимый диапазон — `1..65507`. Это прикладное ограничение ресурсов, а не лимит SADP. Читать на один байт больше, чтобы обнаруживать превышение вместо разбора незаметно усечённого префикса.
- Считать полезную нагрузку недоверенными байтами, сохранять адрес отправителя и передавать обработчику синхронно, как в Python-референсе.
- Не записывать в журналы содержимое пакетов, учётные данные или секреты.
- Использовать сетевые дедлайны или другой поддерживаемый механизм отмены, чтобы отмена контекста надёжно прерывала заблокированное чтение.
- Не выполнять бесконечные повторы. Повторы должны быть ограничены и описаны контрактом запроса либо вызывающим кодом.
- Возвращать типизированную `TransportError` со стабильным этапом (`validation`, `encode`, `write`, `short_write`, `read`, `dispatch` или `close`) и сохранять исходную причину. Отмена контекста должна распознаваться через `errors.Is(err, context.Canceled)`; не классифицировать ошибку по её тексту.
