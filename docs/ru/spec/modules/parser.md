# Спецификация модуля: M2 — Парсер данных

## 1. Назначение

Проверять недоверенные SADP-датаграммы и преобразовывать корректные объявления устройств в типизированные значения Go для логического и пользовательского уровней.

## 2. Обязанности

- Разбирать XML-объявления Python-референса и наблюдаемые сообщения Hikvision `ProbeMatch`/`Hello` стандартным пакетом Go `encoding/xml`.
- Проверять обязательные поля и нормализовать значения, например MAC- и IPv4-адреса.
- Представлять атрибуты устройства типизированными полями Go, а не слабо типизированными картами.
- Возвращать ошибки, позволяющие отличить некорректный XML от отсутствующих или неверных обязательных значений.

Парсер не выполняет сетевой ввод-вывод, не записывает учётные данные в журналы и не реализует рабочие процессы управления устройствами.

## 3. Контракт API Go

Следующие сигнатуры и поля описывают контракт модуля; конкретные пути пакетов и экспортируемые имена будут окончательно определены при реализации:

```go
type Device struct {
    MAC          net.HardwareAddr
    IPv4         netip.Addr
    Activated    bool
    Model        string
    SerialNumber string
    SoftwareVersion string
    Sender       net.Addr
}

func ParseAdvertisement(data []byte, sender net.Addr) (Device, error)
func NormalizeMAC(value string) (net.HardwareAddr, error)
```

- `ParseAdvertisement` получает датаграмму и адрес отправителя от M1 и возвращает проверенное устройство с nil-ошибкой при успехе. При ошибке возвращается ошибка, а модель устройства непригодна для использования.
- Распознавать прямые дочерние поля наблюдаемого `ProbeMatch`: `DeviceDescription` как алиас `DeviceModel` и `DeviceSN` как алиас `SerialNumber`. Если оба алиаса одного значения присутствуют и непусты, но различаются после нормализации пробелов, возвращать ошибку неоднозначности.
- Принимать наблюдаемый корень `Hello` с `Types=hello` как объявление без требования UUID; образец UUID не показывает. Не интерпретировать его как ответ на конкретный probe; иные сочетания корня и `Types` требуют дополнительных данных.
- Обязательны `MAC` и `IPv4`. Если `<Activated>` отсутствует или пуст, устанавливать `Activated = false`, как в Python-референсе; принимать `true`/`false` без учёта регистра и отклонять другие непустые значения. `Model` и `SerialNumber` могут быть пустыми. Если `<SoftwareVersion>` отсутствует, задавать `"Unknown"`, как в референсе.
- Python-референс принимает непустые пакеты до `MAX_PACKET_SIZE` 1500 байт, декодирует UTF-8 с запасным ISO-8859-1 и разбирает XML через `defusedxml`. Значение 1500 не является подтверждённым максимумом SADP. Go может сохранить его как именованный прикладной лимит ресурсов `MaxSADPDatagramSize`, общий для M1 и M2; его нельзя называть максимумом протокола или выводить из MTU Ethernet.
- Референс читает прямые дочерние поля `MAC`, `IPv4Address`, `Activated`, `DeviceModel`, `SerialNumber` и необязательное `SoftwareVersion`; для создания модели он требует только MAC и IPv4. Сохранять эти имена и структуру в тестовых fixtures. Более строгие требования должны быть подкреплены данными устройств и изменением спецификации.
- У наблюдаемого `ProbeMatch` `MAC` и `IPv4Address` остаются обязательными; `DeviceDescription`/`DeviceSN` используются как модель/серийный номер. Прочие поля ответа, включая `Salt`, не входят в текущую модель и не должны попадать в журналы или диагностические сообщения. Наблюдавшиеся значения `flase` в полях `IsModifyVerificationCode` и `DeviceLock` не считать булевым `false` без отдельного обоснованного правила.
- Пустые и слишком большие пакеты, некорректный XML, неверные обязательные значения и неполные объявления являются ошибками Go API, хотя Python-парсер для ряда таких случаев возвращает `None`.
- Неизвестные необязательные XML-элементы можно игнорировать для совместимости с новыми версиями прошивок. Они не должны переопределять обязательные значения или ослаблять их проверку.
- `NormalizeMAC` принимает только поддерживаемые представления MAC-адреса и возвращает канонический `net.HardwareAddr`; при некорректном значении возвращается ошибка, а не частично нормализованный результат.

## 4. Разбор и проверка данных

- Разбирать XML непосредственно из ограниченного по размеру среза байтов с помощью `encoding/xml`; промежуточная строка и сторонняя библиотека XML не требуются. Python-парсер при ошибке UTF-8 использует ISO-8859-1; сохранять такое поведение только при наличии соответствующей проверенной fixture и не менять кодировку молча.
- Python-референс отображает нормализованные MAC в верхнем регистре с разделителями `:`. Go хранит разобранное шестибайтовое значение в `net.HardwareAddr`; стандартный `String()` выводит его в нижнем регистре с разделителями `:`. Это различие представления, а не идентичности адреса. Регистр при сериализации протокола определяется отдельно соответствующей XML-процедурой и требует проверки по fixtures.
- В референсе устройство активно только при значении `Activated`, равном `"true"` без учёта регистра; остальные значения становятся неактивными. Go должен отклонять неизвестные непустые значения, а не считать их `false`.
- Проверять IPv4-адреса через `net/netip`, а аппаратные адреса — средствами `net`.
- Проверять обязательные поля, длину строк и допустимые значения протокола до создания `Device`. Если используется `MaxSADPDatagramSize`, это единый лимит ресурсов приложения для M1 и M2, а не заявленный максимум протокола SADP; лимит 1500 байт Python-референса — исходная точка совместимости, а не правило, выведенное из MTU.
- Сохранять адрес отправителя, полученный от M1, чтобы вызывающий код мог сравнить его с объявленным устройством адресом.
- Не считать, что синтаксически корректный XML обязательно является корректным объявлением SADP.

## 5. Ошибки и диагностика

- Возвращать явные ошибки при некорректном вводе; не записывать ошибку в журнал и не возвращать пустое значение как успешный результат.
- Вызывающий код решает, нужно ли игнорировать, учитывать или сообщать о некорректной датаграмме. Ошибка парсера должна содержать достаточно контекста для принятия этого решения, но не чувствительные данные.
- Не включать содержимое пакета, пароли или секреты в сообщения об ошибках.
- Парсер не должен вызывать панику на произвольных данных. Тесты должны охватывать некорректный XML, отсутствующие поля, граничные размеры пакетов и фаззинг произвольных байтов.
