# Спецификация логирования

## 1. Область и реализация

Логирование является сквозной ответственностью с одной внутренней
реализацией в пакете `internal/logging`. Используется стандартная библиотека
Go `log/slog`; сторонняя библиотека журналирования не требуется.

`internal/logging` отвечает за создание логгера, уровни, параметры handler,
жизненный цикл файлов, ротацию, разделители запусков, общие атрибуты и
редакцию чувствительных данных. Прикладные модули получают `*slog.Logger`
через типизированные зависимости и не создают и не заменяют глобальный
логгер.

Модули, которые пишут записи, импортируют:

```go
import "log/slog"
```

Слой композиции приложения создаёт логгер до запуска любого workflow. Чистые
преобразования могут не импортировать `log/slog`; в их спецификации должно
быть указано, что логирование принадлежит вызывающему workflow.

## 2. Каталог, размер файла и границы запусков

Логи записываются в относительный каталог `.\logs`, вычисляемый относительно
текущего рабочего каталога процесса. Каталог создаётся при инициализации
логирования. Ошибка создания каталога или открытия файла является явной
ошибкой запуска.

Размер каждого файла ограничен **5 МиБ (5 * 1024 * 1024 байт)**. Ротация
выполняется до записи, которая превысила бы лимит. Ротационные файлы
остаются в `.\logs` и используют детерминированные имена без секретных
значений. Одна запись не должна разделяться между файлами.

В начале каждого запуска процесса, до первой обычной записи, handler
записывает пустую строку, затем заголовок с локальной датой и временем
начала логирования, например:

```text

===== logging started: 2026-10-22 21:14:48 +05:00 =====
```

Заголовок записывается для каждого нового запуска, даже если используется
уже существующий файл. Временная метка создаётся один раз при инициализации
логгера. Модули не должны самостоятельно выводить этот заголовок.

## 3. Уровни и общие поля

`logging.level` преобразуется в `slog.Level`:

| Настройка | Уровень |
|---|---|
| `debug` | `slog.LevelDebug` |
| `info` | `slog.LevelInfo` |
| `warn` | `slog.LevelWarn` |
| `error` | `slog.LevelError` |

Стабильные имена событий должны использовать безопасные поля:
`component`, `operation`, `stage`, `interface_index`, `interface_name`,
`sender`, `target`, `payload_size`, `datagram_size`, `count`, `duration`,
`error_kind`, `field`, `command`, `locale`, `mode`.

Ошибки записываются с категорией и стадией. Текст ошибки не заменяет
стабильные поля.

## 4. Редакция данных и владение событиями

Запрещено журналировать пароли, производные от паролей значения, challenge,
токены, полный XML, полный JSON конфигурации, полные сетевые payload и
секретные поля ответов. MAC, серийные номера и идентификаторы устройств
выводятся только при необходимости корреляции и с применением политики
редакции проекта.

Модуль, обнаруживший низкоуровневое событие, пишет технический контекст.
Оркестратор пишет результат workflow. UI пишет границу команды. Вызывающие
слои не должны повторять одно событие только из-за оборачивания ошибки.

## 5. Точки логирования модулей

| Модуль | Обязательные точки | Рекомендуемый уровень |
|---|---|---|
| M0 Adapter | перечисление/выбор интерфейса, open/close multicast, permission/bind/platform failures | info/debug; сбои error |
| M1 Network | write probe/datagram, read, отбрасывание по размеру, dispatch, cancellation, close | debug; отбрасывание warn/debug; сбои error |
| M2 Parser | начало разбора только в diagnostic mode, успешное/отклонённое сообщение, ошибки XML/полей/размера | debug; недоверенные malformed-данные warn/debug |
| M3 Logic | начало/конец workflow, отказ валидации, построение запроса, результат устройства | info; validation warn; сбой error |
| M4 UI | выбор режима, parse/dispatch команды, количество целей, завершение/ошибка команды | info; invalid input warn |
| M5 Localization | загрузка каталога, fallback, смена локали, ошибка decode/read | info/debug; сбои warn/error |
| M6 Discovery | начало/конец сессии, probe, response, parse rejection, timeout, cancellation, cleanup | info/debug; сбои error |
| M7 Configuration | fallback defaults, загрузка файла, validation, precedence, invalid config | info/debug; существующий неверный файл error |
| M8 Application | инициализация логгера, заголовок запуска, сборка зависимостей, startup/shutdown | info; startup failure error |

## 6. Точки логирования процедур

В спецификации каждой процедуры должны быть указаны импорты, события,
уровень, безопасные атрибуты, правило редакции и владелец события.

| Процедура | Обязательная граница события |
|---|---|
| `GetInterfaces` | начало, число подходящих интерфейсов, ошибка перечисления |
| `GetLinuxMAC` | начало, успешное чтение, ошибка чтения/валидации |
| `OpenMulticast` | validation, open socket, close/ownership failure |
| `LoadSettings` | решение defaults/file, decode/validation failure, успех |
| `DiscoverOnInterface` | start сессии, probe cycle, response/rejection, end/cancel |
| `DecodeCatalog` | начало/результат decode, validation failure |
| `ExportTemplate` | start/success экспорта, ошибка destination/write |
| `ListLocales` | начало/результат перечисления, ошибка каталога |
| `Load` (localization) | выбор локали, fallback, ошибка загрузки |
| `MergeCatalog` | validation/result с запретом содержимого каталога |
| `ResolveLocale` | запрошенная/разрешённая локаль, invalid code |
| `SwitchLocale` | начало/успех/ошибка переключения |
| `ValidateLocaleCode` | отказ только в составе пользовательской/config-операции |
| `BuildActivationXML` | validation/build result; XML и secrets запрещены |
| `BuildNetworkXML` | validation/build result; XML и secrets запрещены |
| `CalculateHash` | прямого лога нет; логирует вызывающий workflow |
| `ValidatePassword` | прямого лога нет; логирует вызывающий workflow |
| `DatagramReceived` | размер, sender, parse/dispatch result; payload запрещён |
| `Listen` | start listener, конец loop, cancellation, close failure |
| `SendDatagram` | target, размер, write result; payload запрещён |
| `SendProbe` | target, размер, write result; XML probe запрещён |
| `ParseAdvertisement` | размер/sender/result; source XML запрещён |
| `SanitizeMAC` | прямого лога нет; логирует вызывающая input-операция |
| `DispatchCommand` | start команды, число целей, сводка результатов |
| `ParseCLICommand` | результат parse и безопасная validation failure |
| `ParseCommand` | результат parse и безопасная validation failure |
| `Search` | операция поиска и число результатов; secrets запрещены |
| `SelectMode` | requested/selected mode и terminal validation failure |

Для чистой процедуры без безопасного диагностического события спецификация
обязана явно указать, что записи не создаются, а логирование принадлежит
вызывающей границе workflow.

## 7. Проверка

Тесты используют внедрённый `slog.Handler` или изолированный временный
каталог. Проверяются:

- фильтрация по уровням;
- создание `.\logs`;
- граница ротации до превышения 5 МиБ;
- одна пустая строка и один заголовок времени на инициализацию процесса;
- отсутствие payload, XML, password, challenge, hash и секретов конфигурации;
- стабильные имена событий и обязательные безопасные атрибуты;
- разделение диагностического журнала и text/JSON output CLI.
