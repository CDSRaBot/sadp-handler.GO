# Спецификация процедуры: P0.2 — OpenMulticast
## Модуль: M0 — Адаптер платформы

## 1. Назначение

Открыть UDP-соединение для SADP multicast через явно выбранный сетевой интерфейс хоста.

## 2. Контракт Go

```go
func OpenMulticast(iface Interface, group netip.AddrPort) (net.PacketConn, error)
```

- Отклонять неподходящий или недоступный интерфейс, неверную/не-multicast IPv4-группу либо неверный/нулевой UDP-порт.
- Возвращать соединение, настроенное для указанного интерфейса и группы, либо ошибку без пригодного соединения.
- Вызывающий код владеет каждым успешно возвращённым соединением и обязан его закрыть, если не передал владение M1 `Listen`; `Listen` закрывает соединение при любом исходе.

## 3. Требования к обработке

1. До открытия сокетов проверить выбранный интерфейс и multicast endpoint. Не переключаться незаметно на другой интерфейс или endpoint.
2. Присоединиться к указанной IPv4 multicast-группе через выбранный интерфейс и настроить отправку/приём в соответствии с возможностями целевой ОС. Endpoint Python-референса `239.255.255.250:37020` является целью совместимости, а не авторитетной константой протокола без отдельного подтверждения.
3. Если ОС это поддерживает, привязывать сокет приёма к порту запрошенной группы (в endpoint-е Python-референса используется `37020`). Не копировать ветку Python для Windows, которая привязывает эфемерный порт без присоединения к группе; поведение Windows нужно явно реализовать и проверить.
4. Не устанавливать неподтверждённый multicast TTL и не выводить из него требования обнаружения между подсетями. Любая такая настройка должна быть обоснована проверенным требованием.
5. При ошибке настройки закрыть частично инициализированный сокет и вернуть исходную причину в обёртке с контекстом операции и интерфейса. Не возвращать частично настроенное соединение как успешное.
6. Оставить отменяемое чтение и жизненный цикл цикла приёма модулю M1; возвращённым соединением владеет вызывающий код.

## 4. Пошаговый сценарий поиска устройств

Текущий сетевой контракт описывает приём SADP-объявлений через UDP multicast. Формат и отправка discovery-запроса пока не подтверждены, поэтому открытие сокета само по себе не запускает активный опрос и не гарантирует немедленное обнаружение всех устройств.

1. Получить список сетевых интерфейсов через `ListInterfaces` и предложить выбрать подходящий интерфейс. Исключить loopback, выключенные интерфейсы и интерфейсы без пригодного IPv4-адреса. Не выбирать другой интерфейс незаметно.
2. Открыть multicast-соединение для явно выбранного интерфейса и заданной IPv4 multicast-группы с UDP-портом. Проверить параметры до открытия сокета; присоединиться к группе на этом интерфейсе и привязать порт приёма, если это поддерживается целевой ОС. `239.255.255.250:37020` — цель совместимости с Python-референсом, а не подтверждённая константа протокола.
3. Передать соединение и контекст отмены в M1 `Listen`, вместе с обработчиком датаграмм. После передачи соединением владеет `Listen`, который закрывает его при любом исходе. Вызывающий код задаёт время ожидания/условие остановки отменой контекста; отдельный таймаут поиска здесь не установлен.
4. Для каждой полученной датаграммы сохранить адрес отправителя и проверить допустимый размер до передачи дальше. Передать пакет обработчику синхронно; не запускать неограниченные горутины и не записывать содержимое пакета в журнал.
5. Передать данные парсеру M2 для разбора SADP-объявления. Некорректное объявление обработать как ошибку пакета согласно политике вызывающего кода; не прекращать поиск из-за ожидаемой ошибки разбора. Формат XML и правила обновления списка устройств определяются контрактами M2 и приложения, а не `OpenMulticast`.
6. Показать накопленные результаты обнаружения в вызывающем приложении. При отмене поиска дождаться завершения `Listen` и его закрытия соединения; ошибки транспорта и очистки явно сообщить вызывающему коду.

Этот сценарий описывает получение объявлений, а не полный обмен запрос/ответ. Активную отправку probe и её формат следует добавлять только после подтверждения воспроизводимыми данными устройств.

## 5. Ошибки и тесты

Возвращать явные обёрнутые ошибки неверных аргументов, выбора интерфейса, разрешений, привязки/присоединения к группе и неподдерживаемого поведения платформы. Проверять неверные endpoint-ы, привязку группы к интерфейсу, очистку ресурсов при частичном сбое настройки, поведение поддерживаемых ОС и присоединение к multicast-группе в Windows. Тесты не должны зависеть от внешних устройств или рабочей multicast-сети, если поведение сокетов можно подменить.
