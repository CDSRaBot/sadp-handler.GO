# Спецификация процедуры: P1.5 — handleDatagram
## Модуль: M1 — Сетевое ядро

## 1. Назначение

Проверять ограничения транспортного уровня для полученной UDP-датаграммы и передавать её настроенному обработчику пакетов, не создавая неограниченную асинхронную работу.

## 2. Контракт Go

```go
func handleDatagram(
    ctx context.Context,
    data []byte,
    sender net.Addr,
    maxDatagramSize int,
    handle PacketHandler,
) error
```

`PacketHandler` — тип обработчика модуля M1:

```go
type PacketHandler func(context.Context, []byte, net.Addr) error
```

- Отклонять nil-контекст, отправителя или обработчик, лимит вне диапазона `1..65507`, а также пустые и слишком большие датаграммы с типизированной ошибкой.
- Использовать настроенный общий лимит M1/M2 со значением по умолчанию 1500 из настроек. Это прикладная граница ресурсов, а не подтверждённый максимум SADP. Прослушиватель должен обнаруживать усечение: читать на один байт больше лимита и только затем отклонять слишком большую датаграмму.
- При успехе возвращать nil, полученный от обработчика. Ошибки обработчика оборачивать и возвращать; не преобразовывать их в успешный результат.
- Обработчик не должен сохранять или изменять `data` после возврата, если предварительно не скопировал байты.

## 3. Требования к обработке

1. До передачи проверить длину датаграммы по разрешённому настраиваемому лимиту. По умолчанию — 1500 байт; значение общее для M1 и M2 и не является максимумом SADP. Не записывать содержимое пакета в журнал.
2. Синхронно передать обработчику исходный срез байтов и адрес отправителя. Не запускать неограниченное число горутин — по одной на каждый пакет.
3. Передать обработчику контекст отмены. За отменяемое чтение из блокирующего сокета отвечает прослушиватель; он же решает, приводит ли ошибка обработчика к прекращению прослушивания.
4. Не разбирать SADP XML и не применять правила управления устройствами в этой транспортной процедуре.

## 4. Ошибки и тесты

Для сбоя проверки или передачи возвращать `TransportError` с сохранённой причиной. Некорректный XML обрабатывает M2; он не должен приводить к панике или аварийному завершению прослушивателя. Обработчик уровня приложения решает, является ли типизированная ошибка парсера ожидаемым отброшенным пакетом или сбоем, о котором нужно сообщить.

Тесты должны охватывать nil-аргументы, неверные лимиты, пустые и граничные по размеру датаграммы согласно общей настройке, слишком большие и усечённые пакеты, передачу адреса отправителя, отмену контекста и ошибки обработчика.
