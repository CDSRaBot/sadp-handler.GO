# Спецификация процедуры: P6.1 — DiscoverOnInterface
## Модуль: M6 — Координатор обнаружения

## 1. Назначение

Выполнить один отменяемый сеанс обнаружения на выбранном интерфейсе с периодической отправкой probe в непрерывном режиме либо с ограниченным числом циклов приёма с таймаутом.

## 2. Контракт Go

```go
type DiscoveryOptions struct {
    ProbeInterval time.Duration
    CycleTimeout  time.Duration
    RepeatCount   int
}

func DiscoverOnInterface(
    ctx context.Context,
    iface adapter.Interface,
    options DiscoveryOptions,
    handle EventHandler,
) error
```

- Отклонять nil-контекст/обработчик, неподходящий интерфейс и неверные/смешанные параметры до сетевой активности.
- Непрерывный режим допустим только при `ProbeInterval > 0`, `CycleTimeout == 0` и `RepeatCount == 0`.
- Ограниченный режим допустим только при `ProbeInterval == 0`, `CycleTimeout > 0` и `RepeatCount` в диапазоне `1..100`.
- Возвращать nil при штатной внешней отмене после успешной очистки либо после выполнения всех ограниченных циклов и успешной очистки. Ошибки сокета, отправителя, listener, обработчика или очистки возвращать с контекстом этапа, сохраняя исходные причины.
- Каждый принятый пакет приводит либо к проверенному событию `DeviceFound`, либо к событию `DatagramRejected`. Сохранять адрес отправителя и записывать `ObservedAt`. Доставка всех событий протокольного уровня не должна смешиваться с дедупликацией для отображения.

## 3. Жизненный цикл сеанса

1. Открыть через M0 одно соединение для `239.255.255.250:37020`.
2. Немедленно отправить первый probe через M1 `SendInquiryProbe`. При ошибке закрыть соединение и вернуть ошибку отправки, объединённую с возможной ошибкой закрытия.
3. Запустить M1 `Listen` на том же соединении с дочерним контекстом listener. После передачи соединения `Listen` отвечает за его закрытие; M6 координирует сеанс и запланированные записи. На `net.PacketConn` должен быть ровно один читатель и один сериализованный отправитель; другие компоненты не используют соединение.
4. В непрерывном режиме отправлять последующие probe с интервалом `ProbeInterval`, отсчитываемым после завершения предыдущей запланированной отправки. Продолжать приём между отправками и во время них до внешней отмены.
5. В ограниченном режиме запускать таймер окна приёма после каждой успешной отправки probe. Не завершать цикл раньше при получении устройства. По истечении полного `CycleTimeout` немедленно отправить следующий probe, если остались циклы; после последнего полного окна отменить listener и вернуть управление.
6. Для каждой датаграммы вызвать M2 `ParseAdvertisement` с её отправителем. При ошибке разбора/проверки отправить безопасное событие `DatagramRejected` и продолжать, если обработчик успешен. Для каждого корректного пакета отправлять `DeviceFound`.
7. При сбое запланированной отправки отменить сеанс и вернуть ошибку. При внешней отмене или штатном завершении ограниченного режима сначала остановить и дождаться отправителя, затем отменить контекст listener; после этого дождаться, пока `Listen` закроет соединение и завершит очистку. Если раньше возникает ошибка listener/обработчика, `Listen` может закрыть соединение во время выполняющейся сериализованной записи; остановить и дождаться отправителя, сохранить исходную ошибку и возможные ошибки конкурентной записи/закрытия, не скрывая первичную ошибку. Считать ошибку штатным завершением только если она вызвана отменой сеанса; не считать такой отправленный probe успешным.

Периодичность probe, длительность окон приёма и число повторов являются политикой приложения, а не утверждениями о требованиях SADP. Не сопоставлять UUID, не выводить принадлежность ответа запросу и не считать, что `Hello` вызван конкретным probe.

## 4. Агрегация результатов обнаружения

P6.1 передаёт каждое проверенное событие объявления и не выполняет дедупликацию на границе протокольных событий. Сборщик приложения P4.5 хранит видимый список по нормализованной паре `(MAC, сетевой адрес отправителя)`, обновляет последние проверенные поля и время последнего обнаружения при повторах, а для CLI возвращает снимок, отсортированный сначала по MAC, затем по отправителю. Этот ключ идентичности служит только интерфейсу/приложению.

## 5. Ошибки и тесты

Внедрять зависимости открытия, отправки, прослушивания и разбора через непубличный набор зависимостей либо эквивалентные функциональные точки; не предоставлять тестовые перехватчики в публичном API и не использовать изменяемые глобальные переменные.

Проверять валидацию параметров, порядок отправки/прослушивания, очистку соединения при сбое открытия/первой отправки, немедленное и периодическое расписание, точное число ограниченных циклов и длительность окон, непрерывный приём во время записи, отмену и ожидание горутин, сохранение конкурентных ошибок записи/закрытия, события ошибок разбора с продолжением приёма, доставку `ProbeMatch` и `Hello`, ошибку callback, сохранение отправителя/времени и отсутствие полезной нагрузки в журналах. Тесты не должны требовать реальных устройств или multicast-доступа.
