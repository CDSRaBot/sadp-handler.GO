# Спецификация процедуры: P3.1 — BuildActivationXML
## Модуль: M3 — Логика устройств

## 1. Назначение

Сформировать SADP XML-запрос для активации одного устройства с проверенными учётными данными и необязательной информацией для восстановления доступа.

## 2. Контракт Go

```go
func BuildActivationXML(request ActivationRequest) ([]byte, error)
```

`ActivationRequest` — типизированный запрос M3, содержащий шестибайтовый MAC-адрес, пароль и необязательный адрес электронной почты для восстановления доступа.

- До сериализации проверить все обязательные поля, включая пароль согласно политике M3.
- При успехе вернуть полный XML в UTF-8 и nil-ошибку.
- При неверном вводе или ошибке сериализации вернуть ошибку и не возвращать пригодное для использования сообщение.
- Не записывать пароль, адрес электронной почты для восстановления доступа или сериализованное сообщение в журнал.

## 3. Требования к обработке

1. Проверить MAC целевого устройства как адрес EUI-48 и проверить пароль согласно политике M3. Python-референс требует 8–16 символов и не менее двух классов: строчные, заглавные, цифры или не буквенно-цифровые символы.
2. Формировать XML с помощью `encoding/xml`; не собирать XML-строки конкатенацией недоверенных значений.
3. Использовать подтверждённые имена и регистр элементов запроса:
   - корневой элемент: `<Activate>`;
   - целевое устройство: `<TargetMAC>` с MAC EUI-48 в верхнем регистре и разделителями `:`.
   - учётные данные: `<Password>`;
   - если указан адрес электронной почты для восстановления, добавить `<OptionData><SecurityEmail>…</SecurityEmail></OptionData>`.
4. Поручить XML-кодировщику экранировать текстовые значения. Поскольку `encoding/xml` не добавляет декларацию автоматически, добавить `xml.Header` перед сериализованными XML-байтами.
5. Ограничить срок использования сформированного сообщения текущей операцией. M1 P1.4 `SendSADPDatagram` отправляет payload как одну SADP-датаграмму на multicast endpoint выбранного интерфейса. Запрос идентифицирует целевое устройство через `TargetMAC`; не подменять его HTTP-запросом или endpoint ISAPI. Этот билдер не интерпретирует результат активации и сам по себе не является завершённой операцией активации.

Поля запроса, адресация по MAC и представление XML приняты как контракт совместимости на основе практических экспериментов с устройствами. Считать их нормативными требованиями этой реализации.

## 4. Ошибки и тесты

При неверных входных данных возвращать типизированную ошибку проверки M3, а причины ошибок сериализации сохранять при оборачивании; сообщения не должны раскрывать секреты. Проверять обязательные поля, отклонение пароля политикой, наличие и отсутствие необязательного адреса электронной почты, экранирование XML, точные имена и регистр элементов, а также ошибки сериализации.
