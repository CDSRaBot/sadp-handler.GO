# Каталог fixture протокола мутаций
## Модуль: M3 — Логика устройств

Каталог задаёт семантические сценарии, которые Issue #45 должна закодировать
в детерминированные тестовые fixture. Ожидаемые результаты нормативны.
Каталог содержит отдельные наборы fixture для управления SADP терминала
через ISAPI согласно SDK и для raw SADP UDP mutation. Перехваченный ответ
устройства можно использовать только после утверждения его источника,
корреляции с целью и сопоставления полей.

SDK Hikvision подтверждает следующий набор ISAPI:

- `GET /ISAPI/Publish/TerminalMgr/terminals/discovery/capabilities`;
- `GET /ISAPI/Publish/TerminalMgr/terminals/discovery/<ID>`;
- `PUT /ISAPI/Publish/TerminalMgr/terminals/discovery`;
- корни `DiscoveryMode` и `DiscoveryModeCfg` в пространстве имён
  `http://www.isapi.org/ver20/XMLSchema`;
- `XML_ResponseStatus` для ошибок и для операции `PUT`;
- функциональные коды `0x01400004`–`0x01400007`, перечисленные в
  `parse_mutation_response.md`.

Эти сведения утверждают только грамматику ISAPI fixture. Они не утверждают
поля `TargetMAC`, `SecurityResponse`, challenge, корреляцию отправителя или
ответы мутации raw SADP UDP.

Все тестовые значения синтетические. Имена fixture — стабильные
идентификаторы, а не значения wire-протокола.

## 1. Общие поля fixture

Каждая fixture содержит:

- протокольный набор: `isapi_terminal_sadp` или `sadp_udp`;
- операцию: `activation` или `network`;
- MAC запрошенной цели и ожидаемого отправителя;
- байты запроса либо входные данные билдера;
- байты ответа и фактического отправителя;
- ожидаемое решение или типизированную ошибку;
- ожидаемый результат для устройства;
- значения, которые не должны появляться в логах, ошибках и выводе.

Стенд fixture должен передавать исходные байты ответа как недоверенные
данные и не нормализовать их до передачи парсеру.

## 2.1 Fixture ISAPI управления SADP терминала, подтверждённые SDK

| ID fixture | Запрос | Грамматика ответа | Ожидаемый результат |
| --- | --- | --- | --- |
| `isapi-sadp-capabilities-accepted` | `GET .../discovery/capabilities` | `XML_Cap_DiscoveryMode` | возможности разобраны |
| `isapi-sadp-read-accepted` | `GET .../discovery/<ID>` | `DiscoveryMode` | конфигурация обнаружения SADP разобрана |
| `isapi-sadp-write-accepted` | `PUT .../discovery` | `ResponseStatus` с документированным статусом OK | `accepted` |
| `isapi-sadp-not-activated` | любой поддерживаемый запрос | `MErrCode=0x01400004`, `subStatusCode=notActivated` | терминальная ошибка состояния устройства |
| `isapi-sadp-has-activated` | операция активации/состояния | `MErrCode=0x01400005`, `subStatusCode=hasActivated` | терминальная ошибка «уже активировано» |
| `isapi-sadp-forbidden-ip` | любой поддерживаемый запрос | `MErrCode=0x01400006`, `subStatusCode=forbiddenIP` | терминальная ошибка доступа/авторизации |
| `isapi-sadp-mac-mismatch` | любой поддерживаемый запрос | `MErrCode=0x01400007`, `subStatusCode=bondMacAddressNotMatch` | терминальная ошибка корреляции/авторизации |

Точную успешную пару `statusCode`/`statusString` необходимо брать из fixture
конкретного endpoint. Нельзя выводить успех только из HTTP-статуса.

## 3. Правила утверждения fixture

- Fixture успеха должна указывать точные поля, доказывающие принятие.
- Fixture отказа должна указывать точные поля, доказывающие отказ.
- Fixture повреждённого ответа должна указывать нарушенное правило грамматики,
  не полагаясь на текст ошибки.
- Fixture корреляции должна различать идентичность цели и адрес отправителя.
- Fixture challenge должна указывать время получения, срок действия, MAC
  цели и метаданные отправителя.
- Fixture нельзя считать утверждённой, если ожидаемый результат зависит от
  недокументированного поля или предполагаемого значения статуса.
- Fixture ISAPI должна фиксировать URI, HTTP-метод, XML-корень, namespace,
  поля статуса ответа и раздел SDK-источника.
- Fixture `isapi_terminal_sadp` нельзя использовать повторно как
  `sadp_udp`.
- Fixture `sadp_udp` остаётся неутверждённой, пока грамматика датаграммы,
  идентичность цели, корреляция отправителя и статус ответа не подтверждены
  спецификацией SADP либо утверждённым захватом устройства.
