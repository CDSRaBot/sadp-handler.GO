# Спецификация процедуры: P3.2 — BuildNetworkXML
## Модуль: M3 — Логика устройств

## 1. Назначение

Сформировать SADP XML-запрос для изменения сетевых параметров устройства, включая проверенный ответ защиты, требуемый протоколом целевого устройства.

## 2. Контракт Go

```go
func BuildNetworkXML(
    mac net.HardwareAddr,
    config NetworkConfig,
    challenge string,
    password string,
) ([]byte, error)
```

`NetworkConfig` — типизированная конфигурация M3 с IPv4-префиксом/адресом, необязательным IPv4-шлюзом и признаком DHCP.

- До формирования сообщения проверить MAC, конфигурацию, вызов и пароль.
- Отсутствие вызова является ошибкой. Никогда не помещать пароль в запрос открытым текстом как незаметный резервный вариант для старых устройств.
- При успехе вернуть полный XML в UTF-8 и nil-ошибку; при сбое вернуть ошибку и не возвращать пригодное для использования сообщение.
- Не записывать пароль, вызов, вычисленный ответ или сериализованное сообщение в журнал.

## 3. Требования к обработке

1. Проверить MAC целевого устройства как EUI-48 и применить правила сетевой конфигурации M3. При DHCP статический адрес и шлюз должны быть не заданы; при статической конфигурации адрес и указанный шлюз должны быть корректными IPv4.
2. Вычислить ответ защиты с помощью P3.5 `CalculateHash`. Алгоритм остаётся предметом проверки, описанной в этой процедуре.
3. Сформировать XML `<NetworkParameter>`, определённый протоколом, используя `encoding/xml`:
   - `<TargetMAC>`: канонический MAC-адрес цели;
   - `<DHCP>`: `true` или `false` в нижнем регистре;
   - для статической конфигурации — необходимые по протоколу `<IPv4Address>`, `<SubnetMask>` и `<DefaultGateway>`;
   - `<SecurityResponse>` с вычисленным ответом.
4. Выполнить сериализацию с помощью `encoding/xml`; поскольку кодировщик не добавляет декларацию автоматически, предварить результат `xml.Header`. Не формировать XML форматированием строк.
5. Передать результат модулю M1 для отправки; эта процедура не выполняет сетевой ввод-вывод.

Точные XML-поля, обязательность шлюза и алгоритм ответа защиты необходимо проверить по авторитетной документации протокола или проверенным примерам устройств до заявления о совместимости.

## 4. Ошибки и тесты

Возвращать явные ошибки для некорректных входных данных, отсутствующего вызова, ошибки вычисления хеша или сериализации XML. Проверять ветви DHCP и статической конфигурации, неверную и противоречивую конфигурацию, проверку MAC, подтверждённые векторы «вызов — ответ», экранирование XML, регистр элементов и отсутствие перехода к передаче пароля открытым текстом.
