# Спецификация процедуры: P3.2 — BuildNetworkXML
## Модуль: M3 — Логика устройств

## 1. Назначение

Сформировать SADP XML-запрос для изменения сетевых параметров устройства, включая проверенный ответ защиты, требуемый протоколом целевого устройства.

## 2. Контракт Go

```go
func BuildNetworkXML(
    mac net.HardwareAddr,
    config NetworkConfig,
    challenge string,
    password string,
) ([]byte, error)
```

`NetworkConfig` — типизированная конфигурация M3 с IPv4-префиксом/адресом, обязательным IPv4-шлюзом для статической конфигурации и признаком DHCP.

- До формирования сообщения проверить MAC, конфигурацию, вызов и пароль.
- Отсутствие вызова является ошибкой. Никогда не помещать пароль в запрос открытым текстом как незаметный резервный вариант для старых устройств.
- При успехе вернуть полный XML в UTF-8 и nil-ошибку; при сбое вернуть ошибку и не возвращать пригодное для использования сообщение.
- Не записывать пароль, вызов, вычисленный ответ или сериализованное сообщение в журнал.

## 3. Требования к обработке

1. Проверить MAC целевого устройства как EUI-48 и применить правила сетевой конфигурации M3. При DHCP статический адрес и шлюз должны быть не заданы; при статической конфигурации адрес и обязательный шлюз должны быть корректными IPv4.
2. Требовать непустой challenge и вычислить ответ с помощью P3.5 `CalculateHash`: SHA-256 от UTF-8 `password + challenge` и шестнадцатеричный результат в нижнем регистре.
3. Сформировать подтверждённую XML-форму `<NetworkParameter>` с помощью `encoding/xml`:
   - `<TargetMAC>`: EUI-48 в верхнем регистре с разделителями `:` для fixture совместимости с Python-референсом. Этот регистр не является независимо проверенным требованием протокола.
   - `<DHCP>`: `true` или `false` в нижнем регистре;
   - для статической конфигурации — непустые значения `<IPv4Address>`, `<SubnetMask>` и `<DefaultGateway>`. Отсутствующий шлюз отклонять; не сериализовать пустой элемент;
   - `<SecurityResponse>` с вычисленным ответом.
4. Выполнить сериализацию с помощью `encoding/xml`; поскольку кодировщик не добавляет декларацию автоматически, предварить результат `xml.Header`. Не формировать XML форматированием строк.
5. Считать результат payload для интеграции с транспортом; эта процедура не выполняет сетевой ввод-вывод. M1 P1.4 может отправить SADP-датаграмму, но этот билдер не получает challenge и не интерпретирует результат настройки сети устройства. Не считать один этот билдер завершённой операцией настройки сети.

Форма запроса и расчёт «запрос-ответ challenge-response» приняты как подтверждённые практическими экспериментами. Go не должен копировать fallback Python-референса, который при отсутствии challenge добавляет `<Password>` открытым текстом.

## 4. Ошибки и тесты

Возвращать типизированную ошибку проверки M3 для некорректного ввода или отсутствующего challenge; сохранять причины ошибок вычисления и XML-сериализации. Проверять ветви DHCP и статической конфигурации, отсутствие шлюза, неверную и противоречивую конфигурацию, проверку MAC, подтверждённые векторы «запрос-ответ challenge-response», экранирование XML, регистр элементов и отсутствие перехода к передаче пароля открытым текстом.
