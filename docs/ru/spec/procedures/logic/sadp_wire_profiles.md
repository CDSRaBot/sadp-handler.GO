# SADP wire profiles и optional workflows

Код разделяет операции SADP по wire-профилям. Существующий профиль
`legacy-sha256` сохраняет совместимость с текущим `SecurityResponse`.
Профиль `salted-aes` доступен только через явно переданный проверенный
кодировщик чувствительного поля.

Кодировщик не угадывает длину AES-ключа, KDF, IV, роль `Salt` или формат
`bSalt`. Пока нет воспроизводимого SADP test vector, отсутствие кодировщика
завершает операцию ошибкой и не отправляет payload.

Контрольные вопросы являются отдельной opt-in операцией. Пустой список не
превращается в запрос; три пары вопрос–ответ поддерживаются как типичный
вариант, но не зашиты как универсальное требование. Hik-Connect также
формируется отдельной операцией и не смешивается с активацией или настройкой
сети.

Транспорт может использовать operation-aware matcher: неподходящие или
относящиеся к другой операции датаграммы отбрасываются до истечения
единого deadline. Старые транспорты с методом `Exchange` остаются
совместимыми.

## Статус доказательств для `salted-aes` (Фаза 1–2)

| Элемент | Наблюдение | Источник | Статус |
|---|---|---|---|
| XML-корень | `<Probe>` | `SdkLog_20261028_214108754_w.log`, строки 188 и 200 | подтверждено |
| Операция | `<Types>update</Types>` | тот же SDK-лог | подтверждено |
| Политика ошибок | `<PWErrorParse>true</PWErrorParse>` | тот же SDK-лог | подтверждено |
| Идентичность | `<Uuid>` и `<MAC>` | тот же SDK-лог | подтверждено |
| Секретное поле | `<Password bSalt="true">` содержит непрозрачный Base64-подобный текст | тот же SDK-лог | форма подтверждена, алгоритм нет |
| Соль устройства | `<Salt>` встречается в ответах/объявлениях | `SADP-Activation-Net-DHCP-HC.txt` | связь с `Password` не доказана |
| AES, ключ, KDF, IV, padding | в доступных материалах не определены | capture и SDK-логи | блокер реализации |

Два SDK-запроса подтверждают, что ciphertext меняется между DHCP и static
операциями, но сами по себе не позволяют установить причину изменения:
изменяются сетевые поля и UUID, а контролируемой пары «одинаковый plaintext,
одинаковые параметры, изменён один фактор» нет. Значения пароля, соли и
ciphertext не копируются в репозиторий.

### Контракт до получения вектора

1. `legacy-sha256` выбирается явно и не является доказательством формата
   `bSalt`.
2. `salted-aes` требует внешне проверенный encoder и завершается ошибкой при
   его отсутствии.
3. Нельзя переносить параметры ISAPI `security`/`iv` или documented
   AES-CBC pipeline в raw SADP.
4. Production codec появится только после утверждения вектора, который
   различает алгоритм/длину ключа, KDF, IV, padding и кодирование.

### Следующий вход для Фазы 3

Нужен повторяемый SDK/capture набор для одного устройства и firmware:
одинаковый пароль, повтор запроса без изменения параметров, затем изменение
ровно одного входа за раз (сетевое поле, challenge/exchange code или Salt),
с сохранением XML, UUID, результата устройства и времени. Секретные данные
хранятся вне репозитория; в репозиторий попадает только редактированный
fixture и provenance.

## Результат рекурсивного аудита (Фаза 3)

| Граница | Результат | Решение |
|---|---|---|
| SDK `<Probe>` → Go XML | BLOCKED: текущий builder формирует `NetworkParameter/SecurityResponse`, а не SDK `<Probe>/Password[bSalt]` | не считать builder salted codec |
| Profile selection → encoder | PASS: профиль выбирается явно, отсутствие encoder даёт typed error | сохранить fail-closed |
| Encoder → payload | PARTIAL: injected encoder позволяет тестовый seam, но его output не имеет wire provenance | разрешать только seam до Research |
| SADP ↔ ISAPI | PASS: `security`/`iv` не используются в raw SADP | не переносить ISAPI crypto |
| Error/logging boundary | PASS: штатные ошибки не содержат payload/секреты | добавить negative tests |
| Vector → production codec | BLOCKED: нет controlled plaintext/ciphertext pair | ожидать Research #81 |

Следствие аудита: Фаза 4 может подтвердить только контракт выбора профиля,
fail-closed поведение и отсутствие утечек. Она не может подтвердить алгоритм
или совместимость salted payload с камерой.
