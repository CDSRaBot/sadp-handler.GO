# Спецификация процедуры: P4.3 — ParseConsoleCommand
## Модуль: M4 — Интерфейс командной строки

## 1. Назначение

Разобрать одну строку из командной консоли TUI и преобразовать её в документированную команду приложения. Это только токенизатор и валидатор; процедура не выполняет команды и не запускает shell.

## 2. Контракт Go

```go
type ConsoleCommand struct {
    Command Command
}

func ParseConsoleCommand(line string) (Command, error)
```

- Отклонять пустую строку, неизвестную команду, неверное количество аргументов или недопустимое значение с ошибкой и без пригодной команды.
- Разбивать строку по ASCII/Unicode-пробелам посредством `strings.Fields`; кавычки и shell expansion в командной консоли TUI не поддерживаются.
- Возвращать те же типизированные варианты команд, что используются разбором CLI и диспетчеризацией P4.5.
- Парсер никогда не вызывает OS shell, не выполняет интерполяцию и не трактует ввод как исполняемый код.

## 3. Грамматика

```text
command        = discover | activate | network | language | help | version | quit | export-locale-template
discover       = "discover" [interface-index]
activate       = "activate" [device-mac]
network        = "network" [device-mac]
language       = "language" ("list" | locale-code)
help           = "help"
version        = "version"
quit           = "quit"
export-locale-template = "--export-locale-template" path
```

- `interface-index` — неотрицательный десятичный индекс интерфейса. Если он не указан, использовать интерфейс, явно выбранный в TUI; если интерфейс не выбран, диспетчеризация возвращает понятную ошибку.
- `device-mac` — шестибайтовый MAC EUI-48, принимаемый M2 `NormalizeMAC`. Если указан, это единственная цель. Если не указан, использовать текущий множественный выбор, а при пустом выборе — устройство в фокусе; пустой набор целей является понятной ошибкой.
- `language list` отображает доступные локали. `language CODE` запрашивает точное переключение локали во время работы через M5.
- `--export-locale-template PATH` экспортирует шаблон локали через M5 и несовместим с любой другой командой.
- `activate` и `network` создают типизированные запросы для общей диспетчеризации. До реализации сквозных рабочих процессов возвращать явный результат `unsupported` до открытия формы, запроса секрета, чтения ввода или начала сетевой работы. Это ограничение реализации, а не неподтверждённость выбранной SADP-активации по MAC или расчёта «запрос-ответ challenge-response». После реализации собирать учётные данные только через маскированный UI-ввод; пароли, challenge и производные секреты никогда не передаются командной строкой.
- `help` перечисляет общий каталог команд. `version` показывает версию/идентификатор сборки. `quit` отменяет принадлежащие приложению рабочие процессы и штатно закрывает TUI.
- До реализации полного рабочего процесса команды активации и настройки сети возвращают явную ошибку `unsupported`; это не является протокольным gate для выбранного контракта SADP-активации или подтверждённого расчёта «запрос-ответ challenge-response».
- После проверки синтаксиса и выбора цели передавать типизированную команду через P4.5. Разбор не выполняет поиск цели, не показывает формы, не собирает секреты и не исполняет операции.

## 4. Ошибки и тесты

Ошибки содержат команду/позицию аргумента и причину, но не выводят значения, похожие на секреты, или полную строку команды. Проверять пробелы, пустой ввод, каждую команду и допустимое число аргументов, включая экспорт шаблона локали; неверный MAC/индекс интерфейса/локаль; лишние аргументы; shell-метасимволы и кавычки как обычные символы, не меняющие токенизацию; создание правильного варианта команды и отсутствие побочных эффектов при разборе.
