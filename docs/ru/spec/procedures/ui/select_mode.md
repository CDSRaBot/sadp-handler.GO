# Спецификация процедуры: P4.1 — SelectUIMode
## Модуль: M4 — Интерфейс командной строки

## 1. Назначение

Определить режим взаимодействия процесса по глобальному параметру `--ui` и доступности терминала до запуска рабочих процессов приложения.

## 2. Контракт Go

```go
type InterfaceMode string

const (
    ModeTUI            InterfaceMode = "tui"
    ModeCLIInteractive InterfaceMode = "cli-interactive"
    ModeCLIOnce        InterfaceMode = "cli-once"
)

func SelectUIMode(
    value string,
    once bool,
    stdinIsTerminal bool,
    stdoutIsTerminal bool,
) (InterfaceMode, error)
```

- Если `--ui` не указан, парсер командной строки передаёт `"yes"`. Параметр принимает ровно `"yes"` или `"no"`; другие значения, включая пустое, недопустимы.
- `"yes"` при `once == false` выбирает `ModeTUI`, только если и ввод, и вывод доступны как рабочие терминалы. Иначе возвращается понятная ошибка с рекомендацией `--ui=no`.
- `"yes"` при `once == true` недопустим; `--once` доступен только в CLI-режиме.
- `"no"` при `once == false` выбирает `ModeCLIInteractive` и требует доступный терминал для ввода. Вывод можно перенаправить; приглашения отправляются в stderr, чтобы stdout был доступен для результатов команд. Если stdin не является терминалом, возвращается понятная ошибка с рекомендацией one-shot-вызова с `--once`.
- `"no"` при `once == true` выбирает `ModeCLIOnce` и допускает перенаправленный ввод и вывод.
- При неверном значении параметра или отсутствии необходимого терминала возвращать ошибку и не возвращать пригодный режим. Не переключаться между режимами незаметно.

## 3. Требования к обработке

1. Разобрать и проверить `--ui` и `--once` до начала обнаружения, открытия сокетов или вызова любых других рабочих процессов приложения.
2. Не выводить запрошенный режим из доступности терминала. Проверка терминала нужна только для валидации явно выбранного режима или режима по умолчанию.
3. Зафиксировать разрешённый режим на всё время жизни процесса. Команды могут запускать процессы приложения и показывать результаты, но переход между TUI, CLI REPL и однократным CLI требует отдельного запуска процесса.
4. Проверка терминала находится вне этой чистой процедуры выбора; вызывающий код передаёт признаки возможностей фактических потоков ввода и вывода.

## 4. Ошибки и тесты

Возвращать различимые ошибки для недопустимых сочетаний параметров и отсутствующих необходимых терминалов; не включать чувствительные значения. Проверять значения параметров по умолчанию на границе парсера, точные допустимые значения, недопустимые/пустые значения, требования TUI к терминалам, требование терминального stdin для REPL при перенаправленном stdout, перенаправленные потоки one-shot, запрет `--once` с TUI и отсутствие запуска рабочего процесса после ошибки выбора режима.
