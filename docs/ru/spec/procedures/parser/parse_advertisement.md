# Спецификация процедуры: P2.1 — ParseAdvertisement
## Модуль: M2 — Парсер данных

## 1. Назначение

Разобрать одно SADP XML-объявление, полученное по UDP, и вернуть типизированную проверенную модель устройства.

## 2. Контракт Go

```go
func ParseAdvertisement(data []byte, sender net.Addr, maxDatagramSize int) (Device, error)
```

`Device` — типизированная модель M2, содержащая проверенные MAC- и IPv4-адреса, состояние активации, модель, серийный номер и адрес отправителя.

- Возвращать типизированную ошибку для пустой датаграммы, лимита `maxDatagramSize` вне `1..65507`, датаграммы размером более настроенного лимита или nil-адреса отправителя. Настройки задают общий для M1/M2 лимит по умолчанию 1500 байт. Это прикладная граница ресурсов, а не заявленный максимум протокола; нельзя выводить её из MTU Ethernet.
- Возвращать заполненный `Device` и nil-ошибку только при корректности XML и всех обязательных полей.
- При некорректном XML, отсутствии обязательных полей или неверных значениях возвращать ошибку и непригодную для использования модель.
- Эта процедура не записывает ошибки в журнал и не подавляет их. M1 или уровень приложения решает, как сообщать о некорректном сетевом трафике.

## 3. Требования к обработке

1. До разбора применять настроенный `maxDatagramSize`; M1 должен использовать то же разрешённое значение и обнаруживать усечение до передачи пакета. Значение по умолчанию — 1500 байт, это не подтверждённый максимум SADP. Не включать содержимое пакета в диагностику.
2. Разбирать XML непосредственно из байтов с помощью `encoding/xml`. Python-референс сначала декодирует UTF-8, а при ошибке использует ISO-8859-1; включать fallback только при его подтверждении проверенной fixture.
3. Отклонять некорректный XML, неожиданные данные после документа и директивы XML, не разрешённые форматом SADP. Ограничивать разбор установленным размером входных данных.
4. Извлечь прямые дочерние поля согласно Python-референсу:
   - `<MAC>`: разобрать с помощью `NormalizeMAC` (P2.2). Референс приводит корректный MAC к верхнему регистру и разделяет октеты двоеточиями; Go возвращает ошибку для некорректного значения.
   - `<IPv4Address>`: разобрать как IPv4-адрес с помощью `net/netip`.
   - `<Activated>`: референс считает активным только `true` без учёта регистра, а прочие значения — неактивными. При отсутствии или пустом значении Go устанавливает `Activated = false`; принимает `true`/`false` без учёта регистра и отклоняет неизвестные непустые значения.
   - `<DeviceModel>`, `<SerialNumber>` и необязательное `<SoftwareVersion>`: сохранять полученные значения; модель и серийный номер могут быть пустыми. При отсутствии версии ПО задавать `"Unknown"`, как в Python-референсе.
5. Сохранить `sender` в модели устройства, чтобы вышестоящие уровни могли проверить соответствие источника и адреса.
6. Игнорировать неизвестные необязательные элементы, если это безопасно; они не должны переопределять обязательные значения или ослаблять их проверку. Python-референс использует безопасный XML-парсер `defusedxml` и ищет поля среди непосредственных дочерних элементов.

## 4. Ошибки и тесты

Возвращать `ParseError{Kind, Field, Err}` со стабильными категориями `empty_datagram`, `oversized_datagram`, `malformed_xml`, `unsupported_message`, `missing_field` и `invalid_field`. Сохранять исходную причину через `Unwrap`, не включая полную датаграмму или чувствительные данные. Парсер не должен вызывать панику на произвольном вводе.

Тесты должны охватывать корректные объявления, некорректный и усечённый XML, неверный UTF-8, директивы, данные после документа, отсутствующие и неверные поля, сохранение адреса отправителя, границы настроенного лимита, неизвестные элементы и Go-фаззинг произвольных срезов байтов.
